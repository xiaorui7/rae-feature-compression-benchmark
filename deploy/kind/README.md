# Local Kubernetes demo

The structured manifests are generated by `scripts/serving_kind.py.resources`.
`resources.versioned.example.json` captures the final two-shard deployment;
`resources.example.json` is the historical Phase 4 snapshot. Neither is a universal
dataset path. The generator adapts shard count, immutable export directory,
worker settings, CPU budget and balancing policy. Actual applied manifests live
in ignored `serving_exports/kind-resources.json`.

Prerequisites: Docker, kubectl, kind v0.33.0, Go 1.26.2 binaries in `serving/bin`,
and an exported dataset under `serving_exports`. Node image is pinned to
`kindest/node:v1.35.0`. The image is static/non-root; no registry push is needed.

```bash
python scripts/serving_kind.py up --export serving_exports/export-<hash>
python scripts/serving_kind.py verify --output benchmarks/serving/kind-verification.json
python scripts/serving_kind.py down
```

`up` creates the cluster if absent, builds/imports the image, applies manifests
and waits for rollouts. `verify` checks all oracle queries and requires a positive
query-count delta from both replicas of every shard. `down` deletes only the
named rae-serving cluster. All kubectl operations explicitly use its context and
namespace; they do not depend on the current context.

The kind extraMounts/hostPath arrangement is a single-host demo. Exports are
read-only in the node and pods; the deployment helper explicitly makes selected
export files readable to UID 65532. For a larger deployment, distribute immutable
indices using an artifact store/init container or managed volumes.

Each shard Deployment has two replicas, a headless Service, a separate ClusterIP
Service for the balancing comparison, readiness/liveness/startup probes, resource
requests/limits, PDB minAvailable=1, maxUnavailable=0 and maxSurge=1. PreStop waits
three seconds before SIGTERM; termination grace is 20 seconds, exceeding the
10-second gRPC drain bound. A PDB affects voluntary evictions, not a crash or a
direct pod deletion. Coordinator has two replicas and is reached by loopback
port-forward, with no Ingress or public exposure.

Default `verify` output is the ignored `serving_exports/kind-verification.json`.
An explicit existing path under benchmarks is rejected rather than overwritten.
Temporary process/port-forward logs are also kept inside the workspace's ignored
export parent. Artifact hashes bind Service selectors and immutable coordinator
ConfigMaps to one export version, preventing mixed-format cutover.

Pod templates also carry the local image ID, so `up` rolls updated code even
when its export and image tag are unchanged. An unchanged image/export remains
idempotent. Import chooses the image's actual architecture; recorded tests used
amd64, not an untested ARM deployment.

```bash
python scripts/serving_kind.py bench --output serving_exports/my-bench.json
python scripts/serving_kind.py failures --output serving_exports/my-failures.json
```

The recorded benchmark harness's real-data path and Windows environment collector
are described in SERVING_WALKTHROUGH.md. Actual measured medians/ranges and
retained failed attempts are in docs/SERVING_EVIDENCE.md. The service/Compose CI
is portable to Linux; the local measurement collector is Windows-specific.
